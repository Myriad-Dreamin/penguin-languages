# penguin-languages

Syntax-highlighting plugins for [PenguinHarness](https://github.com/Prism-Shadow/penguin-harness),
one language per plugin. They are external plugins: each is an npm package a Project installs from
the **Plugins** page, which the server downloads from the registry and checks against the plugin
index's integrity.

| Language | Plugin                                                       | Fence                 | File extensions |
| -------- | ------------------------------------------------------------ | --------------------- | --------------- |
| Typst    | [`@penguinharness/language-typst`](plugins/language-typst)   | `typst`, `typ`        | `.typ`          |
| Swift    | [`@penguinharness/language-swift`](plugins/language-swift)   | `swift`               | `.swift`        |
| Kotlin   | [`@penguinharness/language-kotlin`](plugins/language-kotlin) | `kotlin`, `kt`, `kts` | `.kt`, `.kts`   |
| C#       | [`@penguinharness/language-csharp`](plugins/language-csharp) | `csharp`, `c#`, `cs`  | `.cs`, `.csx`   |
| Dart     | [`@penguinharness/language-dart`](plugins/language-dart)     | `dart`                | `.dart`         |

## How it works

The Web App resolves its bundled grammars at build time, so installing something cannot grow that
set. Each plugin hands the server one TextMate grammar through the `LanguagesModule.grammars`
slot. The App lists the language before any grammar loads (the fence aliases and file extensions
come from the plugin's manifest), fetches the grammar the first time a conversation shows the
language, and loads it into the same Shiki core as a bundled one.

A grammar is data, not code: Shiki's JavaScript regex engine interprets it, so nothing on the
path from a plugin to the browser evaluates anything the plugin ships. The grammars are
re-exported from [`@shikijs/langs`](https://github.com/shikijs/shiki), the package the App's own
grammars come from.

## Development

The plugins compile against `@prismshadow/penguin-core`, which the harness lends at run time (a
peer dependency); the language contribution point arrives with core 0.2.14. Until that release is
on npm, build against a harness checkout's core:

```sh
pnpm install
pnpm add -Dw link:../penguin-harness/packages/core   # until core 0.2.14 is published
pnpm test && pnpm build
```

`plugins/*/ifaces.json`, the module table the server checks a plugin against, is generated by the
harness's `gen-ifaces` and committed. Regenerate it after changing a manifest:
`PENGUIN_HARNESS=$PWD/../penguin-harness pnpm gen:ifaces`.

`test/contributions.test.ts` checks every plugin: its grammar is a single document named after the
language, its exported metadata covers every alias and extension the grammar declares, and its
manifest states exactly that metadata.
